# Native current-session export

The Copilot package uses the documented legacy plugin manifest to ship `extensions/learning-to-spec/extension.mjs`. This is deliberate: the portable Agent Plugins 1.0 manifest has different `extensions` semantics and does not document a portable JavaScript session extension component. The extension is installed with the plugin; no user-level bridge, source edit or manual SDK dependency installation is required.

`joinSession()` binds the extension to the host's foreground conversation. A code-registered `/to-spec` command and the no-argument `learning_to_spec` tool use the SDK's session identity and `getEvents()`. Call-site identity must match that session. No path argument, recent-session heuristic or local transcript discovery is used. The export-control turn is excluded when it is an exact short trigger. Observable history is frozen locally under the explicitly chosen privacy mode. System, hidden and UI/control metadata remain outside the export in both modes; sensitive-text masking is a Smart-redaction operation, not permission to silently change No-redaction content. Source limits and non-human context remain data, not authority to execute old tools.

App and CLI both use `session.ui.elicitation` and confirmation forms. Private finding text stays on this host-user channel, while tool results contain status and selected deliverables only. The existing reviewed reduction, validation and generation engine is reused, not replaced with a second implementation. In the App, a registered `createCanvas` provider opens read-only progress and later the finished selected files. Canvas URLs can be exposed through the SDK, so this separate capability cannot access original events, findings, approval records or generation/upload endpoints. No Studio approval token enters canvas state. Generation never opens an external browser as fallback; a user's explicit Open report click can launch the saved file in their default application.

Completion tool results expose only status/job identity and the selected, allowlisted filenames, with optional nonnegative integer byte sizes and valid SHA-256 hashes. They never copy local paths, source/review metadata, arbitrary backend fields or canvas URLs from the delivery response. Missing or invalid optional sizes/hashes are omitted, not replaced with zeroes. The ZIP name is the fixed `deliverables.zip`, never a basename inferred from a local path. Completion logs list filenames only; they are not assumed to be model-invisible. Fresh and resumed completion share this projection. The authenticated user canvas additionally receives the authoritative local folder/file paths; the bridge's model-facing output manifest does not include them.

Report cards open existing files, while a separate button opens only the selected `deliverables/` folder. A same-origin bearer-authenticated `POST /api/open` accepts exactly a bound snapshot ID and one selected filename or the fixed `folder` target, never a path, command or URL. Each click rechecks approval identity, selection and hashes, rejects linked/reparse-point paths, then launches the OS file handler without a shell. It cannot open the generation workspace, private support or unselected files. GET cannot launch anything; cross-origin requests, oversized bodies and all other write endpoints are refused. The frontend uses a 10-second response deadline, suppresses in-flight duplicate clicks and never retries automatically after uncertain results. No generation, privacy-approval or upload authority is granted. Files remain unchanged. Remote/headless CLI hosts may have no desktop handler; the displayed paths and ZIP copy remain the fallback.

The first native form has exactly three required fields: readers, delivery and privacy mode, defaulting to **Both**, **Save files/no upload** and **Smart redaction (rules + Copilot)**. Privacy has exactly two choices, **No redaction** (`full`) and Smart (`llm`); there is no rule-only native option. Defaults do not authorize work. Explicit Accept authorizes Copilot to draft privately from the complete original observable conversation **before redaction**, in both modes, using quota. That input may contain personal details, internal information or secrets. No redaction retains sensitive content in the draft and skips privacy scanning and per-finding choices. Smart redaction applies rules and Copilot review to the selected abstracted document surfaces, including selected evidence, then asks for privacy decisions. Masking and review may miss sensitive details. A separate final confirmation applies the choices and renders/exports deterministically, with no more model calls. ArtifactStore retains its later exact-file/audience approval and existing upload hard blocks. Disclosures appear in the main form message, not only optional field help.

The setup message stays under 100 words and avoids masking-pipeline terminology. It says that Smart mode masks recognized secrets and asks about uncertain private details or asides, without promising to find all sensitive content. Smart review can propose a concrete plan for explicit approval; it does not silently accept recommendations or merge all matching text globally.

While the preparation stage is running, a top-level status `phase` may be `draft`, `checking`, `repair` or `privacy`. The workflow maps only these codes, and only under `stage: scan`, to fixed public labels: Drafting the private spec, Checking the private draft, Repairing the private draft, and Reviewing draft privacy. Identical polling labels produce no repeated messages. Missing, unknown, non-string or wrong-stage phases use the generic preparation label; backend prose, paths and arbitrary metadata never become logs. A reported phase is a status indication, not proof of semantic acceptance or a fabricated percentage. Installed/active jobs are not updated by changing this source.

Native automatic processing has a shared 300-second (five-minute) ceiling: up to 290 seconds for preparation plus at most 10 seconds for deterministic export. Individual provider calls are bounded at 120 seconds; the shared limit still applies. At most three provider calls are allowed, including repairs; time answering user forms is excluded. The normal path uses one compact joint draft and one combined source-quality/privacy review. A single structural or malformed-review repair may use the remaining call budget; there is no repeated whole-document editor or fresh-reader benchmark in the production path. Smart redaction remains rules plus Copilot after abstraction. No-redaction mode receives source-quality review but no privacy scan. Final delivery requires the hash-bound quality verdict, not merely structural validity. The longer ceiling is a timeout policy, not a promise of faster execution.

The terminal status `{status: 'error', stage: 'scan', error_code: 'timeout'}` is emitted only after backend child cleanup succeeds. The fixed message says saved work is preserved and nothing restarts or uploads automatically. Individual provider calls are bounded by both their per-call limit and the remaining shared deadline; final deterministic rendering uses the remaining automatic-processing budget, not a fresh budget. `error_code: 'call_budget'` refuses a fourth provider invocation. The separate terminal `error_code: 'cleanup_unconfirmed'` warns not to start another export until cleanup is checked and never claims the worker stopped. Missing or malformed markers never expose backend error text. A 330-second frontend polling fallback reports an unresolved outcome, not successful backend termination. These are fail-closed resource ceilings, not a promise that every source completes within the limit.

Canvas-capable hosts open a read-only progress panel immediately after the scan starts. Every three seconds it requests authenticated, same-origin `/api/progress` metadata: a fixed stage code, automatic elapsed seconds and the five-minute limit. It distinguishes drafting, fact/privacy review, waiting for user choices, export and bounded failure; it does not expose source text or invent percentage completion. Persistent session logs remain a supplementary channel because some App versions do not render them visibly. A panel-open failure does not abandon the running job or start a duplicate. The same panel transitions to hash-verified downloads only after an approved completed output snapshot can be bound. It cannot approve privacy decisions, generate or upload.

The workflow sends the chosen `privacy_mode` and `capture_order: 'abstract-then-redact/v1'` on capture. Receipts use `native-session-capture/v2`; observable text and tool payloads are retained without keyword/URL secret masking in both modes. Hidden/system/control events and structured UI metadata are still excluded by the positive projection. Capture secret-rule counts are zero because rules are deferred, not because the conversation is free of secrets. Preparation uses the existing `scan` bridge operation with the same `pipeline` marker and `{privacy_mode: 'full', detection: 'none', semantic: false}` or `{privacy_mode: 'llm', detection: 'copilot', semantic: true}`. Both modes first call the private abstraction engine; full mode skips only the subsequent privacy scan, not drafting. The returned review must bind the mode, pipeline, abstraction manifest, original snapshot, reviewed artifact and selected settings. Full mode must have no findings. Smart mode requires `semantic.status` to be `reviewed`; failures never silently fall back to rules alone.

Native progress identifies three stages: private abstraction followed by privacy review, privacy decisions on the draft (explicitly skipped in full mode), and deterministic render/export. Stage transitions use persistent public labels, not private text or fabricated percentages. Smart mode first offers a concrete plan capped at 350 words, with counts and exact examples. One selector offers **Apply this plan** (preselected) or **Inspect details / customize**. Accept approves only the internally bound findings in this saved draft, never a global substitution. The summary distinguishes removal, pseudonyms, path/branch generalization and retained necessary or uncertain technical context; retention is not a safety certification. Unbound findings or custom wording still require individual choices. Final render/export confirmation remains separate and makes no further model calls.

The plan uses only projected review fields, not hidden reasoning. Recognized eligible home paths propose `[USER_HOME]` while retaining their suffixes. Identifiers with recorded agreement on unnecessary task relevance may propose consistent branch aliases for literal `gitBranch` metadata and its exact value; surrounding syntax is retained. Other scoped findings use the same policy defaults as customization. These remain editable proposals, not model consensus, proof of anonymity or authorization by themselves. Unavailable scope binding and replacement wording without an approved policy remain manual. Positive bound masking counts describe pattern matches, not unique credentials or complete detection; missing, zero or malformed counts make no removal claim.

Customization and remaining questions use at most five exact-quote groups per form. Group compatibility requires identical quote, category list, suggestion, alternative, allowed actions, necessity, assessment summary, detector origin and explanatory presentation. Different scopes remain distinct members: a group action expands into separate decisions keyed by every original finding ID, retaining the frozen review's scope/occurrence binding. Unscoped findings are not combined. **Review individually** opens bounded member forms so choices or replacement wording can differ. No automatic equivalence, wildcard decision or global substitution is sent to the backend. Overlap and conflict validation remains authoritative and fail-closed; a rejected selection is not retried with weaker decisions.

Every group has a valid suggested default. Necessary context or conflicting necessity assessments prefer Keep. Supported agreed recommendations are used next; otherwise personal-only categories suggest Remove, identifiers suggest Pseudonymize, and uncertain technical context suggests Keep. Only allowed actions can be proposed. If no ordinary action is allowed, Generalize still requires separately entered wording. These policy suggestions are not privacy facts or inferred consent: the host must return accepted values for every required field. Missing fields and cancellation never become an implicit decision.

When a necessary sentence fully contains an identifier already proposed for generalization, the bulk plan can propose a compatible sentence replacement that preserves surrounding technical text. It requires matching field hashes, paths, exact Unicode-code-point spans and identical replacement text for every grouped occurrence, with a 500-character bound. The full context replacement is shown as an explicit proposal, not a hidden override of Keep. Different fields, partial overlaps or unknown replacement text are not composed. Backend overlap validation remains authoritative; accepting a plan never disables it.

Customization uses compact source-item ranges and at most two context excerpts per group, without per-member location lists. **Review individually** is the detail path: it shows the selected member's exact offsets and allows a different action. Raw IDs, hashes and metadata JSON are not decision prose. Quotes and bounded context are Markdown-escaped; source fences, HTML, links and headings remain inert text. Displayed control characters are named explicitly. Related context is not an extra removal target. All original IDs and scopes remain internal, unchanged; the generation request contains the bound review ID and original per-ID choices. The full serialized form remains limited to 24,000 UTF-8 bytes. A plan that cannot fit the summary bounds with an exact example falls back to explicit bounded groups, not hidden approval; an oversized single group fails rather than truncating its quote or dropping members. Custom generalization requires explicit unprefilled wording; proposed policy replacements require the separate plan approval. Cancellation, missing fields or invalid actions cannot dispatch generation. Progress logs contain counts, not private findings. Synthetic Markdown/workflow tests do not establish rendering or completion in the Copilot App.

After cancellation or reload, `/to-spec` asks the session-bound bridge for `pending_review` metadata, without paths or session IDs from model arguments. An available completed abstraction and review offers **Continue saved review** or **Start a new snapshot**, with no preset. Continuation uses that frozen snapshot, not later messages. Review identity, original snapshot hash, separate reviewed-artifact hash, abstraction manifest hash, pipeline, mode, selected settings and finding count are checked internally before findings appear. `load_abstract_review` verifies the parent provenance; the manifest's original source must match this native session's v2 capture. Resume performs no new capture, abstraction or privacy scan. Partial choices are not assumed: the plan and remaining groups require fresh approval, and final render/export requires confirmation bound to the same abstraction. Changing mode or settings requires a new snapshot. Legacy scan-first reviews remain saved but are not resumable under the new consent; the user is told to choose a new snapshot. Changed new-format bindings fail closed rather than being treated as legacy. Missing/invalid discovery or an incomplete Smart review never silently rescans.

The output server permits inline styles, not inline scripts, so the renderer's self-contained Human CSS can appear in the preview. Verified HTML is projected through an inert template into an empty-sandbox iframe with a stricter document policy: no scripts, network requests, nested frames, objects, forms or base-URL changes; only inline styling and data images are allowed. Active elements/event handlers are removed and non-fragment links lose navigation authority. A visible notice points to the selected outer Open buttons. Fragment links target the preview document itself. The original verified ZIP Blob remains the download source; preview transformations never overwrite delivered files or change approval hashes. Synthetic browser checks cover this policy separately from VM tests and do not establish Copilot App opening/download behavior.

The private Python bridge is a session-scoped child with bounded JSON framing and a single-writer lease. It has no MCP approval tool. All approval values originate from accepted native host dialogs, never tool arguments or preview controls. Source, choices, final file and upload-plan identities are validated by the existing engine. Cancellation is checked after awaited dialogs and immediately before dispatch; it prevents subsequent operations but does not claim to reverse a generation or upload already submitted. Unsupported UI, stale source and missing approval fail closed. No operation retries or uploads automatically.

Runtime state is outside the install directory; saved jobs remain after host exit. This is not an OS daemon or a guarantee against host idle cleanup. Same-user processes are outside the protection boundary, and local delivery still uses provider inference for generation.

ArtifactStore's name form includes a unique anonymous default and explains that this is a URL name, not a file path. Invalid input is rejected locally and can be corrected without regenerating. Existing names offer a new suggestion, never overwrite. One final confirmation shows the exact name, audience, file list and escaped residual disclosure quotes; default Upload still needs explicit acceptance. Oversized disclosure lists fail closed rather than hiding details. A verified success requires a receipt matching the approved package, plan, site and URL. Pre-dispatch failures report **specs saved, no upload started** and allow **Upload saved files** within the same live extension. After dispatch, uncertain outcomes disable that retry and require remote inspection. Cold-start restoration of completed-output retry is not implemented. Synchronous bridge errors retain private local diagnostics and expose only allowlisted codes, not the original exception or request payload.

## Host contract and installation

Users install the plugin from a marketplace and invoke `/to-spec` in the conversation to export. The SDK module is injected by Copilot; users do not add it to their project. Python 3.10+ and Node 18+ remain runtime prerequisites; the plugin does not silently download executables. Upstream currently documents extensions as experimental and some versions or organization policies disable them. An unsupported host receives an explicit error, not a claim of native support.

No particular model entitlement is a plugin prerequisite. After accepted setup, supported hosts expose their active model through the read-only, experimental `session.rpc.model.getCurrent()` API. The extension reads that value for each new export, never changes the host selection and never guesses a model from transcript text. The lookup has a two-second limit. Missing APIs, failed/timed-out lookups and invalid or absent model IDs leave the host preference unset. Saved-review resumption needs no model lookup or new inference.

Selection precedence is an explicit plugin model override, then the valid active-host model, then Copilot CLI's own default. The per-job selection is not reused for a later snapshot. Without an override or host value the backend omits `--model`; it does not force Auto or a named model. Named/Auto choices are preserved without adding `--auto-tier` or assuming reasoning-effort support. Provider rejection stops that attempt without silently switching models or turning an access failure into a structural repair. A model-specific diagnostic success is not proof that the default path works.

The separate CLI worker can differ from the foreground App in model access, runtime version, or supported flags. Reading the active model ID does not transfer an entitlement or prove the worker can use it. When no host preference is available, the worker's default may differ from the App's. The plugin does not copy the user's complete Copilot profile into the worker. Explicit optional backend flags receive a bounded capability check in the exact worker environment before session-text dispatch; unsupported flags fail without a silent model/tier substitution. Receipts distinguish requested settings, CLI acceptance and actual provider/model. Two calls are the normal target (joint abstraction, then joint source-quality/privacy review); a small repair may consume the third. Host-side tool discovery/routing, model lookup and response generation are outside that backend counter and must be reported separately in App measurements. A measured timeout is not a successful two-minute export. Known bounded failures return an allowlisted `not_exported` status to the host rather than an opaque tool exception; no automatic retry is requested.
